## 需求分析

用户需要在转接板指令封装中添加一条启用 OWI 通信模式的指令。

### 示例帧

- **发送**：`55 03 26 01 00 36 22 11 00 04 0D 0B 00 A8 01 29 80 00 00 01 02 00 01 25 26 53 24`
- **返回**：`55 02 36 22 11 26 01 00 00 04 0D 09 00 08 00 01 29 80 00 00 01 B4 0C CE EA`

### 关键发现

1. **目标地址不同**：`0x000126`（端口38），不是转接板内部指令的 `0x000123`（端口35）
2. **功能码 0x0400**：Modbus RTU 转发
3. **数据内容**：完整 Modbus RTU 报文（含 Modbus CRC16）

- Modbus 从机地址: 0x01
- 功能码: 0x29 (F41 写寄存器)
- 起始寄存器: 0x8000 (OWI 通信使能)
- 寄存器数量: 0x0001
- 数据: 0x0001 (启用 OWI)
- Modbus CRC16: 0x2526

### 功能需求

1. 添加通用 Modbus RTU 转发方法 `SendModbusForwardAsync`
2. 添加 `EnableOwiViaConverterAsync` 便捷方法（启用 OWI 通信模式）
3. 添加 `DisableOwiViaConverterAsync` 便捷方法（禁用 OWI 通信模式）
4. 添加单元测试验证帧结构与示例一致

## 技术方案

### 技术栈

- 框架：.NET 6.0
- 协议：CPPI V3.1 + Modbus RTU
- 测试：xUnit

### 架构设计

#### 核心发现

现有的 `_cppiV3FrameStrategy` 已经配置了：

- 目标地址：`0x000126`（端口38）
- 源地址：`0x112236`
- 发送功能码：`0x0400`
- 接收功能码：`0x4900`

这正好是 Modbus RTU 转发所需的配置，无需新增帧策略实例。

#### 实现方案

**1. PS02Base 修改（`#region 转接板指令`）**

在 `#endregion 转接板指令` 之前添加以下方法：

```
/// <summary>
/// 通过转接板发送 Modbus RTU 指令（功能码 0x0400）
/// 转接板将 Modbus RTU 报文透传给下游变送器
/// </summary>
/// <param name="modbusFrame">完整的 Modbus RTU 报文（含 CRC16）</param>
/// <param name="ct">取消令牌</param>
/// <returns>Modbus RTU 响应（不含 CPPI 错误码）</returns>
private async Task<byte[]> SendModbusForwardAsync(byte[] modbusFrame, CancellationToken ct)

/// <summary>
/// 通过转接板启用 OWI 通信模式
/// 向下游变送器写入寄存器 0x8000 = 0x0001
/// </summary>
public async Task EnableOwiViaConverterAsync(CancellationToken ct = default)

/// <summary>
/// 通过转接板禁用 OWI 通信模式
/// 向下游变送器写入寄存器 0x8000 = 0x0000
/// </summary>
public async Task DisableOwiViaConverterAsync(CancellationToken ct = default)
```

**2. 帧构建逻辑**

`SendModbusForwardAsync` 方法：

1. 使用 `_cppiV3FrameStrategy.BuildRawFrame(0x0400, modbusFrame)` 构建 CPPI V3 帧
2. 通过 `SendRawFrameAsync` 发送和接收
3. 使用 `TryParseRawFrame` 解析响应
4. 提取 CPPI 错误码和 Modbus 响应

`EnableOwiViaConverterAsync` 方法：

1. 构建 Modbus RTU 帧：`01 29 80 00 00 01 02 00 01` + CRC16
2. 调用 `SendModbusForwardAsync` 发送
3. 验证响应成功

**3. 测试验证**

在 `ConverterCommandTests.cs` 中添加：

- `BuildRawFrame_EnableOwi_ShouldMatchDocumentSample`：验证帧结构与示例一致
- `TryParseFrame_EnableOwiResponse_ShouldParseCorrectly`：验证响应解析

### 关键实现细节

**Modbus CRC16 计算**（复用 CpplV3FrameStrategy 中的方法）：

```
private static ushort CalculateModbusCrc16(byte[] data, int length)
{
    ushort crc = 0xFFFF;
    for (int i = 0; i < length; i++)
    {
        crc ^= data[i];
        for (int j = 0; j < 8; j++)
        {
            if ((crc & 0x0001) != 0)
            {
                crc >>= 1;
                crc ^= 0xA001;
            }
            else
            {
                crc >>= 1;
            }
        }
    }
    return crc;
}
```

**响应解析逻辑**：

- CPPI 错误码：`frameData[0]`
- Modbus 响应：`frameData[1..]`（8字节）

### 性能考虑

- 复用现有 `_cppiV3FrameStrategy`，无需额外内存分配
- Modbus CRC16 计算复杂度 O(n)，n 为数据长度
- 无额外 I/O 开销

### 错误处理

- CPPI 错误码检查：转接板层面错误
- Modbus 响应验证：下游变送器层面错误
- 超时处理：复用现有 `ReceiveRawFrameAsync` 机制
