# 通用通讯库指令封装提示词

> 基于 DeviceLink 框架的分层架构实践，总结通讯库指令封装的最佳规范。

---

## 1. 项目背景

DeviceLink 是基于 **OSI 五层模型** 的工业设备通信框架：

```
应用层 (DeviceBase + Devices)
管道层 (CommunicationPipelineBuilder)
会话层 (DirectSession / MqttSession)
数据链路层 (DirectDataLink + IFrameStrategy)
物理传输层 (SerialPortTransport / TcpTransport / ...)
协议编解码层 (IProtocolCodec)
```

当需要**新增一个设备类库**时，按照以下规范进行指令封装，确保代码风格统一、类型安全、便于维护。

---

## 2. 目录结构规范

每个设备类库独立一个项目，文件结构如下：

```
DeviceLink.Device.XXX/
├── XXXBase.cs                        ← 设备主类（指令封装）
├── Datas/
│   ├── ModelA.cs                     ← 响应数据模型
│   ├── ModelB.cs
│   ├── ModelC.cs
│   ├── SourceModule.cs               ← 枚举常量（可选）
│   └── VersionModules.cs             ← 枚举常量（可选）
└── DeviceLink.Device.XXX.csproj
```

### 规则

- **所有数据模型**放到 `Datas/` 文件夹，每个文件一个类。
- **设备主类**以 `Base` 结尾（如 `ConST171Base`、`DpsexBase`）。
- **枚举常量类**也放入 `Datas/`，用于替代魔法字符串。

---

## 3. 数据模型设计要求

### 3.1 每个 SCPI 查询指令对应一个强类型模型

不要返回 `string`，要为每个结构化响应定义专用模型。

**正确 ✅：**

```csharp
public class DeviceIdentification
{
    public string Manufacturer { get; set; } = string.Empty;
    public string Model { get; set; } = string.Empty;
    public string SerialNumber { get; set; } = string.Empty;
    public string FirmwareVersion { get; set; } = string.Empty;
    public bool IsValid => !string.IsNullOrEmpty(Manufacturer) || !string.IsNullOrEmpty(Model);
}
```

**错误 ❌：**

```csharp
// 所有查询都返回 string，丢失类型信息
public Task<string> GetIdentificationAsync(...)
public Task<string> GetPressureRangeAsync(...)
public Task<string> GetErrorAsync(...)
```

### 3.2 模型设计要求

- 为每个属性提供 XML 注释，说明含义和单位。
- 提供 `IsValid` 属性用于快速判断数据是否有效。
- 重写 `ToString()` 便于调试日志。
- 使用 `double.NaN` 作为数值类型的无效默认值，而非 `0` 或 `-1`。

```csharp
public class PressureValue
{
    public double Value { get; set; } = double.NaN;
    public string Unit { get; set; } = string.Empty;
    public bool IsValid => !double.IsNaN(Value);
    public override string ToString() => $"{Value} {Unit}";
}
```

### 3.3 枚举替代魔法字符串

对于文档中明确给出的**固定参数值**（如气源名 `Pressure`/`Vacuum`），定义枚举确保编译期类型安全。

```csharp
public enum SourceModule
{
    Pressure,   // 正压气源 / 增压泵
    Vacuum,     // 真空气源 / 真空气泵
    Pre         // 前级泵（仅诊断指令使用）
}

public static class SourceModuleExtensions
{
    public static string ToScpiString(this SourceModule module) => module switch
    {
        SourceModule.Pressure => "Pressure",
        SourceModule.Vacuum   => "Vacuum",
        SourceModule.Pre      => "Pre",
        _ => throw new ArgumentOutOfRangeException(nameof(module), module, null)
    };
}
```

## 4. 设备主类 region 组织规范

严格按以下顺序排列，**顺序不可变**：

```csharp
public class XXXBase : DeviceBase
{
    #region 属性字段
    // 只放 private 字段 / 只读属性
    // 不放任何解析方法
    #endregion

    #region 构造函数
    // 提供多种实用构造方式
    #endregion

    #region 通用指令
    // IEEE488.2 共同指令（*IDN? / *CLS / *RST 等）
    // 系统指令（SYSTem:* 等设备无关指令）
    #endregion

    #region 压力控制指令  （举例，按实际业务命名）
    // 核心业务指令集中放在这里
    #endregion

    #region 私有指令
    // 校准指令 / 诊断指令 / 测试指令 / OTA 等内部指令
    // 所有 private 解析方法放在此 region 的最末尾
    #endregion
}
```

### 4.1 属性字段 region

- 只放字段声明，如 `_codec`、帧分隔符等。
- **解析方法不放在这里**，全部放到「私有指令」region 末尾。

```csharp
#region 属性字段

private readonly ScpiCodec _codec;
private static readonly byte[] CrlfDelimiter = new byte[] { 0x0D, 0x0A };

#endregion
```

### 4.2 构造函数 region

提供以下实用构造器（按需选择）：

| 构造方式 | 适用场景 |
|----------|----------|
| `XXXBase(IPAddress ip, int port)` | TCP/IP 直连 |
| `XXXBase(string ip, int port)` | TCP/IP 直连（字符串 IP） |
| `XXXBase(DeviceCommSettings settings)` | USB / MQTT / 自定义通信配置 |
| `XXXBase(string portName, int baudRate, ...)` | 串口通信 |

**不提供** `ISession` 注入构造器 —— 使用者应通过 `DeviceCommSettings` 或具体传输方式构造。

```csharp
#region 构造函数

public XXXBase(IPAddress ipAddress, int port)
    : base(ipAddress, port, new ScpiCodec("\r\n"))
{ _codec = (ScpiCodec)Codec; }

public XXXBase(string ipAddress, int port)
    : base(IPAddress.Parse(ipAddress), port, new ScpiCodec("\r\n"))
{ _codec = (ScpiCodec)Codec; }

public XXXBase(DeviceCommSettings settings)
    : base(settings, new ScpiCodec("\r\n"))
{ _codec = (ScpiCodec)Codec; }

public XXXBase(string portName, int baudRate = 9600, int dataBits = 8,
    StopBits stopBits = StopBits.One, Parity parity = Parity.None)
    : base(portName, baudRate, dataBits, stopBits, parity,
        new ScpiCodec("\r\n"), CrlfDelimiter)
{ _codec = (ScpiCodec)Codec; }

protected override void ConstructDefaultInfo()
{
    base.ConstructDefaultInfo();
    Name = "XXX";
}

#endregion
```

### 4.3 方法实现规范

每个公开方法遵循 **一行表达式体** 风格：

```csharp
/// <summary>仪器标识查询 —— *IDN?（返回 厂家,型号,序列号,固件版本）</summary>
public Task<DeviceIdentification> GetIdentificationAsync(CancellationToken ct = default) =>
    SendForResultAsync(Command.Read("*IDN"), ParseIdentification, ct);

/// <summary>设置指定气源控制状态 —— PRESsure:CONTrol source,state</summary>
public Task SetPressureControlStateAsync(SourceModule module, bool running, CancellationToken ct = default) =>
    SendNonQueryAsync(Command.Write("PRESsure:CONTrol", module.ToScpiString(), running ? "1" : "0"), ct);
```

#### XML 注释规范

```csharp
/// <summary>
/// 读取双气源实时压力值 —— PRESsure?
/// 返回 正压值,正压单位,真空值,真空单位（如 6.605,kPa,12.408,kPa）
/// </summary>
```

- 第一行：中文功能描述 + `—— 指令原文`
- 第二行（可选）：返回值格式说明或示例

#### 三种发送方式

| 方法 | 用途 | 说明 |
|------|------|------|
| `SendForResultAsync<T>(Command.Read(...), parser, ct)` | 查询指令 | 有返回值，需指定解析函数 |
| `SendNonQueryAsync(Command.Write(...), ct)` | 设置指令 | 无返回值，单向发送 |
| `SendAsync(command, ct)` | 自定义处理 | 返回原始 `byte[]`，外部自行解析 |

### 4.4 私有解析方法

所有 `private` 解析方法集中放在 **「私有指令」region 最末尾**，按使用顺序排列：

```csharp
#region 私有指令

// ... 公共指令方法 ...

// ---- 私有解析方法 ------------------------------------------------------

private static double ParseDouble(string text) =>
    double.TryParse(text.Trim(), NumberStyles.Any, CultureInfo.InvariantCulture, out var v) ? v : double.NaN;

private static int ParseInt(string text) =>
    int.TryParse(text.Trim(), NumberStyles.Any, CultureInfo.InvariantCulture, out var v) ? v : -1;

private static bool IsOne(string text) => text.Trim() == "1";

private PressureValue ParsePressureValue(byte[] raw) { ... }

private DualPressureValue ParseDualPressureValue(byte[] raw) { ... }

// ...

#endregion
```

规则：
- 基础辅助方法（`ParseDouble`、`ParseInt`、`IsOne`）在最前，声明为 `static`。
- 模型解析方法按调用频次或指令顺序排列。
- 每个解析方法内部通过 `_codec.DecodeText(raw)` 拿到文本后自行拆分解析。

## 5. 指令编码规则

### 5.1 SCPI 命令格式（ScpiCodec）

| 命令类型 | `Command.Read` | `Command.Write` |
|----------|---------------|-----------------|
| 格式 | `CMD? param1,param2` | `CMD param1,param2` |
| 示例 | `Command.Read("PRESsure", "Pressure")` → `PRESsure? Pressure` | `Command.Write("PRESsure:CONTrol", "Vacuum", "1")` → `PRESsure:CONTrol Vacuum,1` |

- **查询命令**：使用 `Command.Read(id, params)` → 自动追加 `?`
- **设置命令**：使用 `Command.Write(id, params)` → 不加 `?`
- 多个参数自动以 `,` 拼接，与 SCPI 标准一致。

### 5.2 协议 / 帧策略配置

| 协议类型 | Codec | 帧策略 | 分隔符 |
|----------|-------|--------|--------|
| SCPI | `ScpiCodec("\r\n")` | `DelimiterFrameStrategy` | `\r\n` |
| ConST | `ConSTCodec(address)` | `DelimiterFrameStrategy` | `\0` |
| Modbus RTU | `ModbusRtuCodec(address)` | `ModbusRtuFrameStrategy` | CRC16 |

## 7. 测试文件规范

### 7.1 使用真实构造器

测试中不应手动组装 Session，而是直接使用设备类提供的构造器：

```csharp
private XXXDevice CreateDevice()
{
    return new XXXDevice(TestPortName, TestBaudRate, TestDataBits, TestStopBits, TestParity);
}
```

### 7.2 使用枚举常量传参

```csharp
// ✅ 正确
var result = await device.GetPressureAsync(SourceModule.Pressure);
var fanSpeed = await device.GetFanSpeedAsync(SourceModule.Pressure);

// ❌ 错误 — 不要使用魔法字符串
var result = await device.GetPressureAsync("Pressure");
```

### 7.3 断言强类型属性

```csharp
// ✅ 正确 — 访问强类型属性
var id = await device.GetIdentificationAsync();
Assert.NotEmpty(id.Manufacturer);
Assert.NotEmpty(id.Model);

var range = await device.GetPressureRangeAsync(SourceModule.Pressure);
Assert.True(range.IsValid);
Assert.True(range.Max >= range.Min);

// ❌ 错误 — 仅检查非空字符串
var id = await device.GetIdentificationAsync();
Assert.NotNull(id);
```

## 8. 常见问题

### Q: 有的 SCPI 指令既有查询又有设置怎么办？

查询用 `Command.Read`，设置用 `Command.Write`，分开两个方法：

```csharp
/// <summary>查询锁屏状态 —— SYSTem:LOCK?（true=已启用锁屏）</summary>
public Task<bool> GetLockAsync(CancellationToken ct = default) =>
    SendForResultAsync(Command.Read("SYSTem:LOCK"), r => IsOne(_codec.ExtractString(r)), ct);

/// <summary>设置锁屏状态 —— SYSTem:LOCK state</summary>
public Task SetLockAsync(bool enable, CancellationToken ct = default) =>
    SendNonQueryAsync(Command.Write("SYSTem:LOCK", enable ? "1" : "0"), ct);
```

### Q: 哪些参数应该用枚举？

- 文档中明确列出**固定可选值**的（如 `Pressure`/`Vacuum`/`Pre`）
- 设备类型、通道选择等有限集合的参数
- **不要**对数值范围（如亮度 0-100）、字符串文本（如设备序列号）使用枚举

### Q: 返回值的单位信息如何处理？

- 如果单位由指令固定（如 `PRESsure:RANGe?` 返回单位固定为 kPa），在 XML 注释中说明即可。
- 如果单位随设备配置变化（如 `PRESsure?` 返回值中携带 `kPa`/`psi` 等），模型中必须包含 `Unit` 字段。
